# Phase 10.1, Plan 01: Security Audit Rule Catalog & Static Audit Engine

**Goal:** A versioned, independently-testable static audit rule catalog and engine, evaluable against
the existing `ApkAnalysisInput` snapshot with no new static extraction required (per
`.planning/ROADMAP.md`'s Phase 10.1 goal).

## Must-haves (observable truths this plan must leave TRUE)

1. `DefaultSecurityAuditEngine.audit(input)` evaluates all 8 v1 rules, in a stable, fixed order, for
   any valid `ApkAnalysisInput`.
2. Every rule returns a real `AuditFinding` (never null) — PASS when its condition is not met, WARN or
   FAIL when it is.
3. Every rule has both a trigger-fires and a trigger-does-not-fire unit test.
4. The new catalog's rule IDs (`AuditRuleIds`) share no string with `core:risk`'s existing `RuleIds`.
5. Full project unit-test suite passes with zero regressions against the pre-plan baseline.

## Tasks

1. **Add `AuditModels.kt`** (`core/risk/src/main/kotlin/com/nadeem/apkscope/core/risk/audit/`): `AuditStatus`
   enum, `AuditFinding` data class, `AuditRule` interface, `SECURITY_AUDIT_ENGINE_VERSION` constant.
2. **Add `AuditRuleIds.kt`**: the 8 stable v1 rule ID constants.
3. **Add `StaticAuditRules.kt`**: 8 `AuditRule` object implementations (`DebuggableBuildRule`,
   `SignatureIntegrityRule`, `ExportedSurfaceRatioRule`, `AccessibilityOverlayTapjackingRule`,
   `SmsInternetExfilSurfaceRule`, `BootPersistenceNetworkRule`, `OutdatedTargetSdkRule`,
   `NativeCodeUnverifiedRule`) plus `StaticAuditRules.all`, reusing `Permissions`/`containsAny` from the
   existing `com.nadeem.apkscope.core.risk` package.
4. **Add `SecurityAuditEngine.kt`**: `SecurityAuditReport` data class (with `failCount`/`warnCount`/
   `passCount`), `SecurityAuditEngine` interface, `DefaultSecurityAuditEngine` implementation.
5. **Add `StaticAuditRulesTest.kt`**: fires/does-not-fire test per rule (3 cases average — some rules
   need 2, combination rules need 4 including "neither side" and "only other side"), plus one
   catalog-wide smoke test asserting every rule stamps its own ID.
6. **Add `SecurityAuditEngineTest.kt`**: catalog-size coverage, finding-order-matches-catalog-order,
   count-reconciliation (`failCount + warnCount + passCount == findings.size`), and an all-clean-input
   baseline (every rule PASSes).
7. **Run and record real results**: `./gradlew :core:risk:test --tests "com.nadeem.apkscope.core.risk.audit.*"`,
   then the full suite (`./gradlew test testDebugUnitTest`) to confirm zero regressions. Do not report
   pass/fail counts without having actually run these commands this session.

## Explicit non-goals for this plan

- No UI screen renders a `SecurityAuditReport` (Phase 10.3).
- No persisted analysis is run through the engine end-to-end against a real APK (Phase 10.3, product
  verification).
- No `ApkAnalysisInput` field additions (`usesCleartextTraffic`/`allowBackup`) — tracked separately as
  MS10-STATIC04.
- No automated rule-ID collision guard against `core:risk`'s `RuleIds` — MS10-STATIC02 stays
  source-implemented, not test-covered, until a later pass adds one.

## Verification dependency

Per `docs/SECURITY_AUDIT_VERIFICATION.md`: "component verified" for this plan's rules requires the JVM
unit tests above; "product verified" is explicitly out of scope for this plan and deferred to Phase
10.3. Do not report a status stronger than what this plan's own tests establish.
