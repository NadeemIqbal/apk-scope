# Phase 10.1, Plan 02: Close MS10-STATIC04 and Correct the Outcome Model

**Wired `usesCleartextTraffic`/`allowBackup` through the real analyzer pipeline and replaced the initial
PASS/WARN/FAIL draft with the outcome/severity/confidence model the full Security Audit specification
actually requires — 33/33 audit tests passing, full suite `tests=393 failures=0`, zero regressions.**

## Performance
- **Tasks:** 6/6 completed
- **Files modified:** 11 (0 created — this plan only extended existing Phase 10.1 files)

## Accomplishments
- `ApkAnalysisInput` gained `usesCleartextTraffic`/`allowBackup`, sourced from real
  `ApplicationInfo.FLAG_USES_CLEARTEXT_TRAFFIC`/`FLAG_ALLOW_BACKUP` flags (mirroring how `debuggable`
  was already read) — no proxy signal.
- Two new rules: `AUDIT_CLEARTEXT_TRAFFIC_ENABLED` (FINDING_DETECTED/HIGH/MEDIUM), `AUDIT_BACKUP_ENABLED`
  (NEEDS_REVIEW/LOW/HIGH). Catalog is now 10 rules.
- Replaced `AuditStatus` (PASS/WARN/FAIL) with `AuditOutcome` (6-value vocabulary) + separate `Severity`
  + separate `Confidence` — matching the specification's explicit requirement that severity, confidence,
  and coverage stay separate axes, not conflated into one verdict.
- Added `everyPassedCheck_carriesInfoSeverity` — a catalog-wide guard asserting no rule ever reports a
  non-trivial severity for a `CHECK_PASSED` outcome.

## Task Commits

None — same as 10.1-01, `planning.commit_docs` is `false` and no commit was authorized this pass.

## Decisions & Deviations

See `key-decisions` in frontmatter. This plan was not in the original 10.1-01-PLAN.md — it was added
after receiving the full 22-section Security Audit specification, which named the exact outcome
vocabulary Section 8 requires and confirmed the two manifest fields flagged as a "follow-up" in 10.1-01
were both worth closing immediately rather than deferring further, since `ApkAnalyzer` already computed
one of them (`usesCleartextTraffic`) and the other (`allowBackup`) needed only the same, already-proven
`ApplicationInfo`-flag pattern.
