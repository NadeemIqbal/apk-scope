- **Method Location**: `HttpsInspectionIntegrationTest.kt` (lines 835–1095).
- **Execution Mechanism**: `testPopulateTrafficViewerDemo` performs direct, in-memory insertions into `TrafficInspectionStore.record(TrafficRecord(...))`. It populates 6 synthetic records:

- **Network Stack Interaction**: **NONE**. It does not bind a socket, route packets through the `TunSink` / TUN interface, or trigger `HttpsInspectionEngine`.

### Genuine Acceptance Evidence vs. Gaps for HTTP/2, gRPC, and SSE
- **HTTP/1.1, HTTPS/1.1, and WebSocket RFC 6455**: Fully verified end-to-end through `HttpsInspectionEngine` on device via `testPlaintextHttpGetOnDevice`, `testPlaintextHttpPostOnDevice`, `testEngineInterceptionWithRealPublicHttpsGetOnDevice`, `testEngineInterceptionWithRealPublicHttpsPostOnDevice`, and `testWebSocketUpgradeAndRelayOnDevice`.
- **HTTP/2**: Framing, HPACK decoding, stream tracking, trailers, and resets are verified via unit tests (`Http2FrameParserTest`) and, as of 2026-09-12 (Phase 8.9, see `.planning/STATE.md`), via a genuine ALPN-negotiated relay against a real external server on device (`testHttp2RelayOnDevice` — no longer loopback-piped synthetic frames).
- **gRPC**: 5-byte length-prefix reassembly, decompression, canonical status mapping, and trailer capture are verified via unit tests (`GrpcMessageDecoderTest`) and both a decoder-level device test (`testGrpcInspectionOnDevice`, kept) and a real gRPC-over-HTTP/2 call against Google's public interop server (`testHttp2GrpcRelayOnDevice`, added 2026-09-12).
- **SSE**: Incremental line parsing, multi-line `data:` concatenation, and immediate dispatch before stream closure are verified via unit tests (`SseEventParserTest`) and, as of 2026-09-12, real streams over both HTTP/1.1 (`testHttp11SseStreamingOnDevice`, rewritten off an unreachable `127.0.0.1` target that `DestinationPolicy` correctly denies, onto Wikimedia's recentchange feed) and native HTTP/2 (`testHttp2SseStreamingOnDevice`).
- **RESOLVED (was UNVERIFIED GAP)**: Live **Work Profile VPN preamble → HttpsInspectionEngine → Live Remote Server** forwarding for HTTP/2, gRPC, and SSE is now verified at the `HttpsInspectionEngine` instrumentation-test level — real TLS+ALPN handshake, real frames, real external servers, driven through the same auth-token+IP+port+SNI preamble `TcpProxy` sends in production. This surfaced and fixed two defects (a missing initial HTTP/2 SETTINGS frame to real upstreams, and a buggy `SocketChannel`-adapter upstream socket that silently dropped a write following an earlier one on the same connection) plus a design gap (the upstream ALPN offer was unconditional; a fallback now reconnects it without h2 when the real downstream client can't speak h2 but the real upstream can) and a case-sensitive-header defect breaking SSE/chunked detection against real servers. Full detail in `.planning/STATE.md` Phase 8.9. **Still not done**: the `TcpProxy` packet-capture-to-preamble handoff itself was not independently re-verified this pass, and no new fixture-app-in-Work-Profile traffic-viewer screenshots were taken for these three protocols.

## 3. Provenance & Protocol Claims

### URL Provenance Integrity
- **Rule**: `RUNTIME_OBSERVED` requires an *exact* URL match with real transaction evidence. A host
  match alone must never elevate provenance — it attaches separate, non-elevating `hostCorrelation`
  metadata instead. (Corrected 2026-09-12 — this section previously quoted an older, host-level
  `contains()` check that the working tree had already replaced with the exact-match model below
  before this pass began; the quote was stale, not a description of a regression.)
- **Implementation Verification (`DexUrlExtractor.kt`, `MutableCandidate.toCandidate`)**:
  ```kotlin
  val exactEvidence = observedRuntimeUrls[normalizedUrl]
      ?: observedRuntimeUrls[normalizedUrl.trimEnd('/')]
      ?: observedRuntimeUrls[originalString]
  val hostInfo = observedRuntimeHosts[host.lowercase(Locale.ROOT)]
  val provenance = when {
      exactEvidence != null -> UrlProvenance.RUNTIME_OBSERVED
      references.isNotEmpty() -> UrlProvenance.REFERENCED_BY_CODE
      else -> UrlProvenance.PRESENT_IN_DEX
  }
  // hostInfo is attached as candidate.hostCorrelation regardless of provenance — it never
  // participates in the provenance decision above.
  ```
  Verified in `DexAnalysisTest` (host-only match asserted to never produce `RUNTIME_OBSERVED`;
  exact-URL match asserted to produce it with `runtimeEvidence` populated). **Production wiring**:
  `ApkAnalyzer.analyze()` gained an `observedRuntimeHosts: Set<String>` parameter this pass, threaded
  to `DexUrlExtractor` and verified against the real fixture APK
  (`testApkAnalyzerAttachesHostCorrelationOnDevice`) — this covers host-level correlation only.
  Nothing yet calls it with *real* observed hostnames from a completed sandbox run (that needs a
  merge onto an already-persisted analysis, deliberately not built this pass — see
  `.planning/STATE.md`), and exact-URL `RUNTIME_OBSERVED` has no production path at all: the only
  existing cross-profile evidence artifact (`RuntimeObservationArtifact`) carries per-connection
  hostnames, not full HTTP transactions (no URL/method/status), so it cannot support exact-URL
  matching even once wired.

### HTTP/2 Protocol Verification
- **Verified Capabilities**:
  - Pseudo-header mapping (`:method`, `:path`, `:scheme`, `:authority`, `:status`).
  - HPACK stateful header compression/decompression via OkHttp `Http2Reader`.
  - Concurrent stream tracking by `streamId` using thread-safe `ConcurrentHashMap`.
  - HTTP/2 Trailers parsing (HEADERS frame without `:status`).
  - Stream reset (`RST_STREAM`) handling with error code mapping (`TrafficCaptureState.ERROR`).
  - 64 KiB bounded payload buffering with truncation flags.
- **Unverified Edge Cases**:
  - Heavy concurrent multiplexing under network congestion / packet drop.
  - Dynamic HPACK table desynchronization across proxy boundaries.
  - Flow control window exhaustion (`WINDOW_UPDATE` backpressure across unequal client/server window sizes).
  - ~~End-to-end live ALPN `h2` forwarding in `HttpsInspectionEngine`~~ — **resolved 2026-09-12**, see Phase 8.9 in `.planning/STATE.md`.

### gRPC Protocol Verification
- **Verified Capabilities**:
  - 5-byte length-prefix framing: 1-byte compression flag + 4-byte big-endian length.
  - Incremental frame reassembly across chunk boundaries and byte-by-byte feeds (`testMessageSplitAcrossChunks`).
  - Multiple messages packed into a single DATA frame (`testMultipleMessagesInOneDataChunk`).
  - Bounded gzip decompression (`testCompressedGzipMessage`).
  - Canonical gRPC status code mapping (0..16) from trailers (`grpc-status`, `grpc-message`).
- **Unverified Edge Cases**:
  - Complex streaming RPCs (bidi streaming with long idle periods) through live VPN forwarder.

### Server-Sent Events (SSE) Protocol Verification
- **Verified Capabilities**:
  - WHATWG EventSource specification compliance: `data:`, `event:`, `id:`, `retry:`, `:comment`.
  - Multi-line `data:` concatenation with `\n`.
  - Real-time event emission upon encountering terminal empty line (`\n\n`) *before* the connection closes (`testSingleLineDataEvent`, `testMultiLineDataEvent`).
  - Incremental arrival across buffer boundaries (`testChunkedArrivalAcrossBuffers`).
  - Bounded line buffer protection (64 KiB).
- **Unverified Edge Cases**:
  - Live long-lived EventSource connections over cellular networks with carrier-initiated TCP timeouts.

### HTTP/3 and QUIC Feasibility
- **Status**: Strictly **Experimental / Observational Telemetry (Decryption Deferred)**.
- **Implementation**: `QuicPacketParser.kt` parses unencrypted UDP port 443 datagrams to extract:
  - Long Header vs Short Header (1-RTT) discrimination.
  - Packet type decoding: Initial, 0-RTT, Handshake, Retry, Version Negotiation.
  - Version identification (QUIC v1, QUIC v2, gQUIC, drafts).
  - Destination and Source Connection IDs.
- **Decryption Status**: **NOT IMPLEMENTED**. In accordance with architecture decision document `docs/HTTP3_QUIC_FEASIBILITY.md`, full MITM decryption of HTTP/3 requires bundling native C/Rust QUIC stacks (e.g. Quiche/MsQuic) across 4 Android ABIs, adding 15–30 MB overhead. QUIC datagrams are forwarded unmodified via `UdpNat`.
- **Classification Rule**: `isConfirmedHttp3` is hardcoded to `false` on observational captures. Packet classification is never represented as decrypted HTTP/3 inspection.
